## What worked

- Storage and recovery were fault-tested at every persistence boundary and the
  transaction protocol held; the acceptance suite found defects in integration,
  not in the primitives.
- Interface tests through named widgets (ADR 0013) made the P7 interface work
  measurable and gave every control an accessible name.
- Continuous integration on both platforms, with real directory layouts
  asserted after migration and creation.
- Decisions and evidence were written down as they were made; this
  retrospective could be built from the repository alone.

## What did not

- **The default mode shipped without the block library panel.** The
  specification described transactions, sessions, recovery and migration over
  437 lines and never listed the screens. The folder window keeps the board's
  `Add step` menu and the `+` on cards, so built-in blocks and components can
  still be added one at a time; what is gone is the panel itself — search, the
  Blocks / Variables / Operators sections, operator chips, dragging a block
  onto the board — and scenario navigation while in Diagram mode. `library.rs`
  is used only by the legacy window, and the empty board still says "Drag a
  block from the library". Allowed by: no screen inventory and no mock-up in
  the analysis; no owner approval of what the change would look like.
- **Migration refuses the owner's real workspace** ("a scenario differs after
  reloading"), and the default start was flipped regardless. Allowed by: no
  acceptance test on real data; the exit evidence was a test count.
- **Backward compatibility was treated as a requirement** and shaped the
  architecture, although the owner did not need it. Allowed by: no rule that
  compatibility, migration, defaults and removals are the owner's decisions.
- **Fifteen chained branches** made review impossible and turned "a human
  merges after review" into a formality. Allowed by: no rule that a branch
  starts at `main`, and no size or WIP limit.
- **Tests and code were written in the same session by the same author**, so
  the tests confirmed the implementation's assumptions. Thirty-five `fix`
  commits against forty `feat` commits, all before any user saw the result.
  Allowed by: no acceptance-test-first rule.
- **An open architectural decision was hidden as an ignored test.** Allowed
  by: no rule binding an ignore to a ticket.
- **Technical detail displaced product information.** The owner received ADRs
  and verification logs, not a picture of the result. Allowed by: no template
  separating the owner's page from the technical appendix.

## What surprised us

- 961 green tests and a 10/10 interface gate said nothing about the two
  defects that matter most to the owner (no palette, migration refused).
- Native QA ran only on Linux while the owner also works on Windows; the
  Windows CI job already captures screenshots and could have been the evidence
  channel all along.
- The whole stage, including its specification, was produced in one weekend;
  nothing in the process slowed it to the speed at which it could be read.
