# UX-04: *Running unsaved code* moves to the window header, only while the run runs

- Size: S · Owner review: 15 min · Risk: `visible UI`
- State: Analysis (issue #101; resolves #152) · decisions taken by the owner
  on 2026-11-02 on the UX-00 mock-up (#97, approved as a whole) · acceptance
  criteria posted on #101 on 2026-11-02 and carried below · no decision
  open · UX-1 sprint, wave 1 ([plan](../sprints/ux-1.md)) · **after UX-02**
  (both touch the header's run controls) · labelled `ready:opus`
- Analysis model: Fable · Implementation model: Opus

## Goal

While a run runs, the header says what runs, just left of *Cancel run*,
naming the file when another tab is active. When the run ends, the words go
with it: nothing about the run stays in the band under the tabs.

## What the owner will see

- New: a grey label in the header, immediately left of *Cancel run*, for
  the run's whole life: *Running unsaved code* (hover: *The run uses the
  code in the editor, which is not saved yet.*), *Running saved code*, or
  *Running earlier code* (hover: *The editor's code has errors; the run uses
  the last confirmed code and configuration.*). On another tab it names the
  file: *Running unsaved promotion-and-cart-price.afs*, *Running saved …*,
  *Running earlier …*. *Cancel run* takes the place of the run controls
  meanwhile, which leaves the label its room at 960 px.
- Changed: the three *Running …* notices no longer appear in the band under
  the tab strip, so the workspace does not move down when a run starts and
  nothing is left to dismiss after it (#152).
- Removed or hidden: nothing; the three messages move, the third shortened
  to *Running earlier code* with its full sentence on hover.
- Migrated or converted: nothing. Default behaviour that changes: none.

## Decisions taken (owner, 2026-11-02, quiz on the UX-00 mock-up, on #101)

> - *Running unsaved code* sits in the header **just left of *Cancel run***
>   (`ux04-beside-cancel-960x540`).
> - It shows **only while the run runs**.
> - It is grey. On another tab it names the file that runs, for example
>   *Running unsaved promotion-and-cart-price.afs*.
> - The mock-up was approved as a whole (`mock/ux-00` at `2c1fa79`, `ux04-*`).

The posted criterion 1 extends the rule to a run of saved code (*Running
saved code*), which is what resolves #152; the analysis extends it the same
way to the third band message (the confirmed earlier code), so that no
*Running …* notice is left in the band. No decision is open.

## Acceptance criteria

Criteria 1–4 are the ones posted on #101 (2026-11-02), each made testable;
5–7 are added by this analysis. Tests are in
`crates/apiforge-desktop/src/folder/acceptance_tests.rs`, `mod ux04`, on the
demo shop project. A run that is still running when the test looks is a
live run against a loopback listener that accepts and never answers, as the
mock-up's view does; the run is cancelled at the end.

1. While a run runs, the header shows a grey label just left of *Cancel
   run* — *Running unsaved code* after an unsaved valid change, *Running
   saved code* otherwise — and the band under the tab strip holds no
   *Running …* notice. Testable form: the label is in `theme::MUTED` at
   `theme::FONT_LABEL`, its rect is on *Cancel run*'s row with its right
   edge left of *Cancel run*'s left edge by at most the item spacing plus
   8 px, and the unsaved label carries the hover text above. Tests:
   `ux04_criterion_1_unsaved_code_is_said_left_of_cancel_run`,
   `ux04_criterion_1_saved_code_is_said_too`. Refinement: a run accepted
   through *Run this version* while the code is invalid reads *Running
   earlier code* with its hover (`ux04_criterion_1_earlier_code_is_said`).
2. The label is gone the frame the run ends — passed, failed or cancelled
   — and the band holds no notice from it. Tests of the three ends: a
   simulation that passes, a live run whose listener closes the connection
   (failed), and *Cancel run*:
   `ux04_criterion_2_the_label_goes_when_the_run_{passes,fails,is_cancelled}`.
   The pull request says `Closes #152`.
3. With another tab active while the run runs, the label names the file:
   *Running unsaved promotion-and-cart-price.afs* (the same for saved and
   earlier); back on the run's tab it reads *Running unsaved code*. Test:
   `ux04_criterion_3_another_tab_names_the_file`.
4. The implementation matches `ux04-beside-cancel-*` and
   `ux04-component-tab-960x540` at 960 × 540 and 1600 × 1000: the QA report
   compares them, on Linux and from the Windows CI artifacts. A simulation
   ends in milliseconds, so the QA scenario runs live against a local socket
   that never answers (`nc -l 127.0.0.1 <port>` with the project's base URL
   set to it) and cancels the run afterwards; the report says so. The
   verification commands of the development guide pass.
5. Added: the header fits. At 960 × 540 and 1600 × 1000, in Code, Diagram
   and Split, with *Live allowed* shown, on the scenario's tab and on a
   component's tab (*Publish*), the project name, the three mode tabs,
   *Save*, *Save all*, *Publish*, *Live allowed*, the label and *Cancel run*
   are within the window and disjoint. Test:
   `ux04_criterion_5_the_header_fits` with `assert_within_window` and
   `assert_disjoint`.
6. Added: the label is a labelled widget for assistive technology (its text
   is its name) and is not focusable. Test:
   `ux04_criterion_6_the_label_is_named` (`accessibility_tests.rs` pattern).
7. Added: KTLO-19's rendering note (the maximised report starts under the
   notice) no longer applies to runs: after a run, the maximised panel
   starts under the tab strip. Covered by KTLO-19's tests in
   `report_tests.rs`, which pass unchanged.

## Technical appendix

- `folder/runs.rs::start_run_with`: the three `notify(message, false)` calls
  go; the prepared run already carries `unsaved` and `last_valid`, and
  `runs.active` holds it while the run runs. A helper
  `running_label(&self, active_tab) -> Option<(String, &'static str)>`
  returns the text and the hover: `None` when no run runs; *Running
  unsaved code* / *Running saved code* / *Running earlier code* on the
  run's own tab; *Running unsaved <file>* and so on elsewhere, the file from
  `file_name(&snapshot.path)` of `active.document_id()`.
- `folder/chrome.rs::header`: in the right-to-left row, after *Cancel run*
  (so to its left), `ui.label(RichText::new(text).size(theme::FONT_LABEL)
  .color(theme::MUTED)).on_hover_text(hover)` as the mock-up's
  `unsaved_run_label`. The `reserved` width: *Cancel run* is narrower than
  UX-02's button and chevron, so the label needs no extra reservation on a
  scenario's tab; on a component's tab the mock-up's `header_fits` held at
  960 px with *Publish* and *Live allowed*, which criterion 5 keeps.
- `poll_run` clears nothing: there is no notice to clear. The mock-up's
  band filter (`in_header`) is not needed once the notify calls go.
- The mock-up's `mock_ux00::Unsaved` switch is not merged; the review view
  `review_ux04_unsaved_notice` is rewritten against the real label (the
  held listener stays its device) and added to `testing::review`.
