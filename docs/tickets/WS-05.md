# WS-05: A scenario's title is shown above its board and where a test is chosen

- Size: S · Owner review: 10 min · Risk: `visible UI` (M · 15 min if the
  title is editable in the header)
- State: **Analysed, waits for the owner's choice on the board** (issue
  #574, `decision-needed`) · the same on v0.1.0 and v0.2.1-rc.2, not a
  regression · REQ milestone
- Analysis model: Fable 5.2 · Implementation model: Opus

## Goal

A tester who knows a test by its title finds it and knows which test is
open, without opening Code.

## Finding

Looked at on `main` (`1923fcd3`). The header above the board is
`folder/diagram.rs`, `Header` (the file name and the kind); a row of
*Files* is `folder/explorer.rs`, `explorer_row` (the file name; the path
on hover). The title is `Scenario::name` of the document's model, which
the session holds for every registered document, open or not.

*Files* has no filter and the window has no quick-open: option A of the
issue, "found by it in the list's filter", has nothing to stand on. It
is left out of A here and proposed apart (below).

## Acceptance criteria (A, editable)

Tests in `folder/acceptance_tests/ws05.rs`.

1. In Diagram the header shows the scenario's title, then the file name,
   then the kind; a component shows its name the same way. `header_shows_title`.
2. As the row narrows the kind goes first, then the file name (whole or
   not at all), then the title ends in an ellipsis; hover on the title
   gives the title and the file name. At 960 × 540 with the long fixture
   nothing overlaps the tabs or the toolbar (`assert_disjoint`).
   `header_gives_way_in_order`.
3. A document whose code has errors and no valid model keeps today's
   header (the file name). `header_without_a_model`.
4. Hover on a scenario's or component's row of *Files* reads the title,
   then the path; other rows as today. `files_hover_names_the_title`.
5. The title follows an edit in Code after the analysis, in the header
   and the hover. `title_follows_the_code`.
6. A double click on the title opens a field with the title selected;
   Return writes the line (one undo step, the document dirty), Escape
   and an empty text change nothing; a quote or a backslash is written
   escaped and read back the same. Not offered when the board is
   read-only. `title_is_edited_in_the_header`.
7. Split is unchanged (the header there has no name).
   `split_header_unchanged`.
8. Design review at 960 × 540 and 1600 × 1000 against the board.

## Proposals of the planning model

- **A way to find a test by its title** (new ticket, not in WS-05): a
  filter field above *Files* that matches file names and titles, or
  *Go to test* on a key. It is what A promised and what the wrong turns
  of round 2 were looking for; it needs its own board.
- The tab's hover shows the title too (the same text as the row's hover):
  inside A at no cost, criterion 4 if the owner agrees.
- Run results' header and the exported result's name carry the title:
  REP-05 #363.

## Files touched

`folder/diagram.rs` (`Header`, `HeaderFit`), `folder/explorer.rs`
(`explorer_row`), `folder/chrome.rs` (the tab's hover), the edit through
the existing model edit of the document; `folder/acceptance_tests/ws05.rs`,
`testing.rs` (a review view).

## Regression risk

The header's fit at narrow widths (KTLO-12, `header_tests.rs` covers the
order of giving way and must be extended, not replaced); the steps
summary beside it. The edit writes the first line of the file: REQ-13
#540 (the window writes only what was set) holds, since it writes on
Return only.
