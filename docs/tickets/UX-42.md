# UX-42: The run mode is a switch in the header

- Size: S · Owner review: 20 min · Risk: `visible UI`, `removal`
- State: **Approved, ready for implementation** (issue #520) · decided
  by the owner on 2026-11-21 on the mock-up: **C, a switch in the
  header**, no menu; the line *The Run button runs this mode until you
  change it.* is **dropped**; *Review legacy runs* **moves to the Project
  menu**; and, on the measurement, question 12 = **A**: where the
  header's row is too short the Run button is ▶ alone · for 0.2.1 ·
  found by the owner on the v0.2.0-rc.1 packages, 2026-11-21 · labelled
  `ready:opus` · implemented on PR #530: acceptance tests `d82da3e`,
  implementation `7e03072` and `db3dd9c`
- Analysis model: Fable 5.2 · Implementation model: Opus

## Goal

"The run mode choice is ugly." The mode is no longer chosen in a menu:
*Simulation | Live* stands in the header beside the Run button, always in
view, one click to change.

## What the owner will see

- New: a two-part switch, *Simulation | Live*, left of the Run button.
  The chosen part is white with its word in the mode's colour (violet,
  accent); the other is muted. A click changes the mode at once and runs
  nothing. The mode is kept as UX-02 keeps it, per person and project.
- Changed: the Run button reads *▶ Run* in both modes and keeps the
  mode's colour and UX-02's hover texts. Where the header's row is too
  short for it — today a component's tab with *Live allowed* below about
  1000 px — it is ▶ alone in the mode's colour, named on hover
  (decided, question 12 = A).
- Removed: the chevron *Run options* and its menu with the caption RUN
  MODE, the two hints and the line *The Run button runs this mode until
  you change it.* (decided). The hints become the hover texts of the
  switch's parts.
- Moved: *Review legacy runs* is an item of the Project menu, after
  *Test environment…* (decided). The *Runs* button that holds only this
  item on a tab that cannot be run goes with it.
- While the window observes (MCP-08a): the *Live* part is disabled with
  UX-02's hover, the switch shows *Simulation* and the stored mode is
  kept, as today.
- While a run is running the switch is not drawn: the row shows *Cancel
  run* and the running label, as today.

- **A — the Run button drops its word only where the row is too short
  (chosen):** on a header that cannot hold *▶ Run*, the button is ▶

  about 1000 px.
- B — the Run button is ▶ alone, always: one look everywhere; the
  window's main action loses its word.
- C — the caption *rN · no changes* leaves the header where the row is
  too short and stays on *Publish*'s hover (about 84 px back; UX-25's

- D — back to the menu with whole rows (option A of question 2).

## Acceptance criteria

Tests in `crates/apiforge-desktop/src/folder/acceptance_tests/ux42.rs`;
UX-02's tests of the menu are rewritten with them.

1. The header of a tab that can be run holds *Simulation*, *Live* and
   the Run button, in that order from the left, and no *Run options*.
   `ux42_criterion_1_switch_and_button`.
2. A click on a part chooses the mode, writes it as UX-02 does
   (`run-mode.json`, this project only), recolours the Run button and
   starts no run. `ux42_criterion_2_a_click_changes_the_mode_only`.
3. The parts are one radio group for assistive technology, each named
   *Simulation* or *Live* with its state; Tab reaches the group before
   the Run button; Left and Right move the choice.
   `ux42_criterion_3_keyboard_and_names`.
4. While the window observes, *Live* is disabled with UX-02's hover, the
   switch shows *Simulation*, and the stored *Live* returns when the
   window holds the project again. `ux42_criterion_4_observing`.
5. *Review legacy runs* is in the Project menu and opens what it opens
   today; no *Runs* button is drawn on any tab.
   `ux42_criterion_5_review_legacy_runs_in_the_project_menu`.
6. On a component's tab with *Publish*, *rN · no changes* and *Live
   allowed*, at 960 × 540 and in both modes, every control of the header
   is within the window and at least 8 px from its neighbour; the same on
   a scenario's tab; the project's name keeps the width it has in v0.2.0.
   On that component's tab the Run button is ▶ alone, in the mode's
   colour, with the accessible name and hover of its mode; on every
   header that holds *▶ Run* with those 8 px, at 960 × 540 and at
   1600 × 1000, it reads *▶ Run*. The choice follows the row's measured
   width, not the kind of tab. `ux42_criterion_6_the_fullest_header_fits`.
7. The title does not move when the mode changes (UX-02's rule): the
   row reserves the same width in both modes. `ux42_criterion_7_title_stays`.
8. Design review at 960 × 540 and 1600 × 1000, both modes, a scenario's
   and a component's tab, compared with the approved captures.

## Not in scope

A confirmation before a live run, the SIMULATION badge, MCP-09's *Live
allowed*. Where the mode is kept (UX-02).
