# UX-42: The run mode menu reads as two choices

- Size: S · Owner review: 15 min · Risk: `visible UI`, `removal`
- State: Analysis (issue #520) · mock-up posted, **decision needed** (questions 2–4) ·
  for 0.2.1 · found by the owner on the v0.2.0-rc.1 packages, 2026-11-21
- Analysis model: Fable 5.2 · Implementation model: —

## Goal

"The run mode choice is ugly." The menu beside the Run button shows two
modes as two things to pick, and nothing else competes with them.

## What is wrong today

The content is UX-02's (#99), decided on 2026-11-02; its form is the
problem. Each mode's grey hint stands outside the row it explains, so the
highlight covers only the word *Live*; the items are indented 8 px and
their hints are not; a third grey line and two separators follow; and
*Review legacy runs*, which is not a run mode, ends the list in the
strongest text of the menu.

## What the owner will see

- Changed: the menu's form, options A, B, C below. The mode, where it is
  kept, the button's two labels and colours, and *Live* being disabled
  while observing are UX-02's and stay.
- Removed or hidden (question 3): the line *The Run button runs this mode
  until you change it.* is not drawn in any option; the mark on the
  chosen row says it.
- Moved (question 4): *Review legacy runs* stays in the menu, in the
  muted colour, in A and B; C has no menu, so it goes to the Project menu.

| Option | Look | For the person at the window |
| --- | --- | --- |
| **A — whole rows (recommended)** | Caption RUN MODE; each mode one row holding its name and its hint, a dot in the button's colour, a check and a tint on the chosen one | Everything UX-02 says, in two targets instead of seven lines; the violet and the accent tie the row to the button |
| B — commands | *Run simulation* / *Run live*, no caption, hints on hover | The smallest menu; a newcomer no longer reads what a simulation is, and a row named like the button looks as if it started a run |
| C — a switch in the header | *Simulation \| Live* left of a button that reads *Run*; no chevron, no menu | The mode is always in view and one click away, also by accident: *Live* sends requests. Not measured on a component's tab with *Publish* and *Live allowed* at 960 px |

## Acceptance criteria

Tests in `crates/apiforge-desktop/src/folder/acceptance_tests/ux42.rs`;
UX-02's tests of the menu's lines are rewritten with them.

1. The *Run options* menu holds the caption, the rows *Simulation* and
   *Live* and *Review legacy runs*, in that order, and no other text
   outside the rows (after question 3). `ux42_criterion_1_menu_content`.
2. A click anywhere in a mode's row, also on its hint, chooses the mode;
   the row is one accessible item named *Simulation* or *Live*, chosen or
   not. `ux42_criterion_2_the_whole_row_chooses`.
3. The chosen row carries the check and the colour of the Run button of
   that mode. `ux42_criterion_3_chosen_row_matches_the_button`.
4. While the window observes, *Live* is disabled with UX-02's hover and
   the row keeps its hint. `ux42_criterion_4_live_disabled_while_observing`.
5. Up, Down and Enter move and choose as in any menu; Esc closes and
   writes nothing. `ux42_criterion_5_keys`.
6. Design review at 960 × 540 and 1600 × 1000, both modes, compared with
   the approved capture.

## Not in scope

The Run button itself, the SIMULATION badge, MCP-09's *Live allowed*.
